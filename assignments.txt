PERSON 1: core_logic.py (Login, Text Analyzer & Ticket ID Maker)
====================================================================
Note: Only use datetime, re, and nltk. Do NOT import sqlite3 or streamlit.

[ ] 1. Setup Constants & Keyword Dictionaries
    - Goal: Paste the shared lists at the top of the file and create your
      keyword dictionaries (SYNONYM_MAP for issue tags and SCOPE_TRIGGERS
      for hostel/floor/room locations).

[ ] 2. Build Login Checker
    - Function: authenticate_user(input_id: str, input_pwd: str) -> dict
    - Goal: Check if the username and password match USER_IDS and PASSWORDS,
      and return the AuthPayload dict.

[ ] 3. Build Complaint Text Analyzer
    - Function: parse_complaint_text(title: str, description: str) -> dict
    - Goal: Read the title and description, find matching location words and
      problem keywords using NLTK, decide the scope (Hostel > Floor > Room),
      pick the issue tags and priority (High/Medium/Low), and return the
      NLPAnalysisPayload dict.

[ ] 4. Build Ticket ID Generator
    - Function: generate_uid(scope_tag: str, priority: str, issue_tags: list[str], monthly_seq: int) -> str
    - Goal: Combine the inputs into a single formatted ticket ID string like
      "HSTL-HI-WAT-2611-0001".

[ ] 5. Test in Terminal
    - Goal: Run the file by itself with test strings to make sure all 3
      functions return the exact dictionary keys listed in Part 1.

PERSON 2: database.py (SQLite Database & Queries)
====================================================================
Note: Use sqlite3, json, and datetime. Always return database rows as
standard Python dicts (not raw tuples) so Person 3 and 4 can use key names.

[ ] 1. Create Database Connection & Tables
    - Functions:
      get_connection() -> sqlite3.Connection
      init_db() -> None
    - Goal: Connect to "complaints.db" and create the 6 tables if they don't
      exist yet (Complaints, Comments, Comment_Votes, Subscriptions,
      Thread_Bans, Audit_Logs).

[ ] 2. Build Monthly Ticket Counter
    - Function: get_next_sequence_number(yymm: str) -> int
    - Goal: Count how many tickets already exist for the current year/month
      and return that number + 1.

[ ] 3. Build New Complaint Saver
    - Function: create_complaint_record(uid: str, author_id: str, title: str, description: str, scope_tag: str, issue_tags: list[str], priority: str) -> None
    - Goal: Save the new complaint into Complaints (converting issue_tags to a
      JSON string), subscribe the author in Subscriptions, and add a "created"
      note in Audit_Logs.

[ ] 4. Build Complaint Fetchers
    - Functions:
      get_all_complaints() -> list[dict]
      get_user_complaints(user_id: str) -> list[dict]
      get_complaint_by_uid(uid: str) -> dict | None
    - Goal: Fetch all complaints (newest first), fetch complaints a user is
      subscribed to (unread alerts first), or fetch one specific complaint.

[ ] 5. Build Subscription & Notification Bell Helpers
    - Functions:
      subscribe_user(user_id: str, uid: str) -> None
      trigger_notifications(uid: str, exclude_user_id: str) -> None
      clear_user_notification(user_id: str, uid: str) -> None
      get_unread_notification_count(user_id: str) -> int
    - Goal: Add users to a thread's subscription list, turn on the unread
      alert flag (1) for subscribers except the person who caused the update,
      clear the flag (0) when they open the thread, and count unread alerts.

[ ] 6. Build Comment & Audit Log Fetchers
    - Functions:
      get_comments(uid: str) -> list[dict]
      get_audit_logs(uid: str) -> list[dict]
    - Goal: Return all comments or audit logs for a specific complaint UID
      so the UI can display them.

PERSON 3: workflows.py (Rules, Voting Math & Admin Actions)
====================================================================
Note: Import database.py to read and update tables.

[ ] 1. Build Ban Checker
    - Function: is_user_banned(uid: str, user_id: str) -> bool
    - Goal: Check the Thread_Bans table and return True if the user is banned
      from that complaint thread, or False if they are allowed.

[ ] 2. Build Comment & Auto-Subscribe Workflow
    - Function: post_comment_workflow(uid: str, user_id: str, content: str, is_solution: bool) -> tuple[bool, str]
    - Goal: Block the comment if the user is banned. Otherwise, save the
      comment to Comments, auto-subscribe the user to the thread, trigger
      notifications for other subscribers, and return (True, message).

[ ] 3. Build Close Issue Workflow
    - Function: close_complaint_workflow(uid: str, actor_id: str, actor_role: str) -> tuple[bool, str]
    - Goal: Allow only the complaint's author or an admin to close the ticket.
      Count current subscribers, save that number into initial_sub_count, set
      status to "CLOSED", notify subscribers, and log it in Audit_Logs.

[ ] 4. Build Solution Voting & 2/3 Auto-Reopen Workflow
    - Function: cast_solution_vote_workflow(comment_id: int, uid: str, voter_id: str, vote_delta: int) -> dict
    - Goal: Block banned users. Record the user's upvote (+1) or downvote (-1)
      and update the comment's totals. If the complaint is "CLOSED" and a
      solution reaches upvotes >= (2/3) of initial_sub_count, automatically
      reopen the complaint, notify everyone, log it, and return VoteResultPayload.

[ ] 5. Build Admin Moderation Workflows
    - Functions:
      ban_user_from_thread(uid: str, admin_id: str, target_user_id: str) -> tuple[bool, str]
      admin_modify_complaint(uid: str, admin_id: str, new_scope: str, new_tags: list[str], new_priority: str, new_status: str) -> None
    - Goal: Let admins ban a user from a thread (making sure the complaint
      author can never be banned) and let admins edit a complaint's tags,
      scope, priority, or status while logging changes in Audit_Logs.
